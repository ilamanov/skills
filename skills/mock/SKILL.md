# Mock

## Goal

Let the user see a change before it is built. The user decides by looking, not by imagining.

## Steps

1. **Find the options.** Find the different ways that the change can look or behave.
2. **Make a mock for each option.** Use the real styles of the product. A mock can be a page, a prototype, or a screenshot.
3. **Show the mocks together.** Tell the differences between them.

## Rules

- Make the mocks fast. Do not build the real feature.
- Keep the mocks out of the product code.
